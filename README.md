# Extending and improving a survival analysis dashboard

This repository contains the source code and documentation for a final degree project focused on extending an interactive web application for survival analysis of university student dropout.

The application is built with Python and Dash. It supports uploading and preprocessing academic data, running several survival analysis techniques, visualizing results, generating interpretations with local artificial intelligence, and exporting PDF reports.

## Main features

- Upload, validation, and preprocessing of an academic dataset.
- Clean dataset inspection and descriptive covariate analysis.
- Survival analysis techniques:
  - Kaplan-Meier.
  - Cox regression.
  - Log-Rank test.
  - Exponential model.
  - Weibull model.
  - Random Survival Forest.
- Indicative comparison of techniques.
- Spanish and English language support, with English selected by default in this copy.
- Explanation generation using a local AI model.
- PDF export of results, tables, charts, and interpretations.

## Main modules

| File | Responsibility |
| --- | --- |
| `cargaDataset.py` | Initializes Dash, registers callbacks, and starts the local web server. |
| `layout.py` | Defines the visual structure of the dashboard pages. |
| `analysis_callbacks.py` | Connects the interface to models, tables, charts, and AI. |
| `preprocesamiento.py` | Validates the CSV, reduces the dataset, and builds one representative row per student. |
| `kaplan_meier.py`, `cox_regression.py`, `log_rank_test.py` | Implement classical survival analysis techniques. |
| `exponential.py`, `weibull.py`, `rsf.py` | Implement the techniques added by this project extension. |
| `ollama_AI.py` | Builds academic prompts and calls the local OpenAI-compatible server. |
| `pdf_exporter.py`, `pdf_callbacks.py` | Generate PDF reports from the results selected by the user. |
| `translations.py` | Centralizes translatable Spanish and English interface text. |

The code is documented with comments and docstrings to support review. This README provides a general overview rather than an exhaustive source code manual.

## Requirements

Environment used during development and testing:

- Windows 11.
- Python 3.13.2.
- Dash 3.1.0.
- Libraries listed in `requirements.txt`.

Recommended installation:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Running the dashboard

From the project root:

```powershell
python cargaDataset.py
```

Alternatively, use the included script:

```powershell
.\START_DASH_APP.bat
```

Then open the following address in a browser:

```text
http://127.0.0.1:8050
```

## Local artificial intelligence module

AI is optional. Statistical analysis works even when the AI server is inactive.

Automatic explanations use a local OpenAI-compatible API server run with `llama-server`. The default configuration expects:

```text
models/qwen2.5-1.5b-instruct-q4_k_m.gguf
tools/llama.cpp/llama-server.exe
```

These files may be absent from GitHub because of their size or because they are external resources. Place them at these paths or configure the `MODEL_PATH` and `LLAMA_SERVER` variables.

Start the AI server:

```powershell
.\START_LLAMA_SERVER.bat
```

Default endpoint:

```text
http://127.0.0.1:8000/v1/chat/completions
```

## Expected dataset

The application uses an academic CSV containing at least the columns required for analysis:

- `id_student`
- `date`
- `final_result`
- `gender_F`
- `disability_N`
- `age_band_0-35`
- `age_band_35-55`
- `age_band_55<=`
- `highest_education_A Level or Equivalent`
- `highest_education_HE Qualification`
- `highest_education_Lower Than A Level`
- `highest_education_No Formal quals`
- `highest_education_Post Graduate Qualification`
- `studied_credits`

Preprocessing validates the structure, converts the final result into a dropout event indicator, consolidates student records, and generates the clean dataset used by the models.

## Usage workflow

1. Start the dashboard.
2. Upload a valid CSV.
3. Run preprocessing.
4. Review the clean dataset.
5. Open the analysis modules:
   - covariate analysis,
   - Kaplan-Meier,
   - Cox,
   - Log-Rank,
   - Exponential,
   - Weibull,
   - Random Survival Forest,
   - technique comparison.
6. Review tables, metrics, and charts.
7. Optionally request an AI interpretation.
8. Export the results to PDF.

## Tests and benchmarks

The report's testing chapter documents functional validation of the main use cases. Additional scripts measure AI module performance:

```powershell
python benchmark_ia.py
python benchmark_ia_lucia.py
```

Results are stored in:

```text
benchmarks/
```

These measurements compare response times and approximate resource usage on the test computer. They provide a practical evaluation of the configurations used in the project, rather than a universal comparison of models.

## Notes for the assessment panel

- The application runs locally and does not require an external server deployment.
- The AI module helps interpret results and complements statistical analysis.
- The system is an exploratory support tool for studying patterns associated with academic dropout, rather than an automatic decision system.
- The LaTeX report documents objectives, background, requirements, design, implementation, tests, limitations, and conclusions.
